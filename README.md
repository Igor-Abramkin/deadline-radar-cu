# deadline-radar-cu

Telegram-бот, который следит за дедлайнами в LMS Центрального университета
(my.centraluniversity.ru) и пишет о них в группу курса или направления.

- 🆕 в LMS появилось новое задание
- 📅 / ⚠️ / 🔥 до дедлайна осталось 3 дня, сутки или 3 часа
- 🔁 дедлайн перенесли
- `/deadlines` присылает сводку на две недели и закрепляет её, а бот
  обновляет её после каждой проверки LMS
- 📆 необязательно: календарь с дедлайнами, на который можно подписаться
  в Apple, Google, Яндекс Календаре или Outlook
- 📚 необязательно: отдельная тема с расписанием: каждое утро пары на сегодня,
  а если пару перенесли или отменили, бот сразу пишет об этом
- 🗳 необязательно: обратный отсчёт до конца конкурса в группе и итоги

Каждый запускает свою копию: бот видит LMS через аккаунт того, кто его
настроил, и присылает задания его курсов.

## Быстрый старт

Нужны [Bun](https://bun.sh) и Git.

```sh
git clone https://github.com/Igor-Abramkin/deadline-radar-cu
cd deadline-radar-cu
bun install
bun run setup
```

`bun run setup` проводит через пять шагов:

1. **Бот в Telegram.** Создаёшь бота у [@BotFather](https://t.me/BotFather)
   и вставляешь токен, мастер проверяет его.
2. **Вход в LMS.** Открывается браузер, входишь как обычно: логин, пароль,
   капча, код из SMS. Мастер сохраняет сессию в `data/cookie.txt`.
3. **Группа.** Добавляешь бота в группу и делаешь администратором с правами
   на удаление и закрепление сообщений. Потом пишешь любое сообщение в тему,
   куда бот будет присылать дедлайны. Мастер сам узнаёт id группы, темы и твой,
   проверяет права администратора и отправляет в группу проверочное сообщение.
4. **Расписание и календарь**, по желанию. Для темы с расписанием мастер
   просит iCal-ссылку на календарь, показывает ближайшие пары из него
   и узнаёт id темы по сообщению, которое ты в ней напишешь. Для календаря
   дедлайнов спрашивает домен, на котором будет работать бот.
5. **Запуск.** Мастер записывает `.env` (для запуска на своём компьютере) и
   `deploy.env` (для сервера) и показывает инструкцию для выбранного хостинга.

Инструкцию по запуску можно открыть ещё раз командой `bun run deploy`.

> `deploy.env` и `data/` дают доступ к твоему аккаунту в LMS, а ссылка
> на экспорт календаря в `deploy.env` открывает все его события. Они уже
> в `.gitignore`: не коммить их и никому не отправляй.

## Где запускать

Боту нужны исходящие соединения с `api.telegram.org` и
`my.centraluniversity.ru`. Входящие запросы он принимает, только если включить
календарь дедлайнов (`PUBLIC_URL`, см. ниже). Подойдёт любая площадка,
которая умеет:

- собрать `Dockerfile` из репозитория или запустить `bun src/bot.mjs`;
- передать переменные окружения из `deploy.env`;
- хранить `/app/data` на постоянном томе. Без него после перезапуска бот
  забудет, о чём уже писал, и потеряет обновлённую сессию LMS.

Мастер показывает готовые шаги для Coolify, Dokploy и похожих панелей,
Docker Compose (`docker-compose.yml` лежит в репозитории), `docker run`,
Bun с systemd и запуска на своём компьютере.

Бот с одним токеном может работать только в одном месте. Если запустить его
на сервере, локальную копию нужно остановить.

## Команды бота

- `/deadlines` — сводка на `LIST_DAYS` дней. В группе можно писать из любой
  темы: бот удалит команду и пришлёт сводку в тему дедлайнов, закрепив её
  вместо предыдущей. В группе команда срабатывает не чаще раза в час
  (`GROUP_COOLDOWN_SEC`), повторы бот удаляет без ответа. В личке лимит —
  раз в 30 секунд на человека (`PRIVATE_COOLDOWN_SEC`).

  Пока новых `/deadlines` нет, бот после каждой проверки LMS (`POLL_MINUTES`)
  редактирует закреплённую сводку: пересчитывает, сколько осталось, добавляет
  новые задания и убирает прошедшие. Внизу написано время последнего
  обновления.
- `/help` — что умеет бот.
- `/chatid` — id чата и твой id, только для владельца.
- `/session <cookie>` — обновить сессию LMS, только для владельца в личке.

На владельца (`OWNER_ID`) лимиты не действуют.

## Когда истекает сессия LMS

Сервер LMS продлевает сессию на 14 дней при каждом запросе, а бот ходит туда
каждые 30 минут, так что обычно она не истекает. Если всё-таки истечёт, бот
напишет владельцу в личку. Тогда:

```sh
bun run login
```

Скрипт откроет браузер, после входа выведет команду `/session …`. Отправь её
боту в личку, и он продолжит работу.

## Календарь дедлайнов

Если задать `PUBLIC_URL`, бот запускает веб-сервер на порту `PORT`
(по умолчанию `3000`) и отдаёт:

- `PUBLIC_URL/deadlines.ics`: все дедлайны из LMS, включая прошедшие,
  с напоминаниями за сутки и за 3 часа;
- `PUBLIC_URL/`: страницу с кнопками «подписаться» для Apple и Google
  и инструкцией для Яндекс Календаря.

Календарь пересобирается после каждой проверки LMS. Ссылку на страницу бот
показывает в `/help`.

Календарю нужен домен с HTTPS, направленный на сервер. Тема с расписанием
работает без него. Как подключить домен:

- **Coolify, Dokploy и похожие панели:** указать домен в настройках
  приложения, порт `3000`. Сертификат панель получит сама.
- **Docker Compose:** `docker compose --profile calendar up -d --build`.
  Профиль запускает Caddy, который берёт домен из `PUBLIC_URL` в `.env`
  и сам получает сертификат. Порты 80 и 443 должны быть свободны.
- **`docker run` или systemd:** любой прокси с HTTPS на `localhost:3000`.
  С Caddy это две строки в `/etc/caddy/Caddyfile`:

  ```
  cal.example.com {
    reverse_proxy localhost:3000
  }
  ```

`bun run deploy` показывает те же шаги под выбранный вариант.

Приложения календарей сами решают, как часто перечитывать подписку:
Apple и Outlook обновляют её за минуты или часы, Google — раз в несколько
часов. Поэтому о переносе дедлайна бот в Telegram сообщит раньше, чем
изменится календарь.

## Расписание

Бот может вести отдельную тему с расписанием из любого календаря с экспортом
в iCal. В Яндекс Календаре ссылка лежит в настройках календаря → «Экспорт»
(`https://calendar.yandex.ru/export/ics.xml?private_token=…`). Проще всего
подключить её через `bun run setup`, вручную — положить ссылку
в `SCHEDULE_ICS_URL`, а id темы в `SCHEDULE_THREAD_ID`.

- Каждый день в `SCHEDULE_TIME` (по умолчанию `09:00`) бот присылает пары
  на сегодня: время, название, аудиторию и ссылку на звонок. Сообщение
  закрепляется, а если в течение дня что-то поменяется, бот его обновит.
  В день без пар сообщение приходит без звука.
- Раз в `SCHEDULE_POLL_MINUTES` минут (по умолчанию 15) бот сверяет календарь
  и пишет, если на ближайшие `SCHEDULE_DAYS` дней (по умолчанию 7) пару
  перенесли, отменили, добавили или сменили аудиторию. Более далёкие правки
  не присылает, чтобы массовые изменения на семестр вперёд не заваливали тему.

Ссылка на экспорт открывает весь календарь, поэтому бот берёт только события,
у которых организатор — `SCHEDULE_ORGANIZER` (по умолчанию
`timetable@centraluniversity.ru`). Личные события в группу не попадут.
Как и с LMS, бот видит расписание того, чей это календарь: пары других
уровней и треков в тему не попадут.

## Конкурс

Если в группе идёт голосование или конкурс с дедлайном, бот может отсчитывать
время до конца и объявить победителя. Для этого нужна ссылка на JSON
с результатами в `CONTEST_URL`:

```json
{
  "title": "Голосование за название группы",
  "url": "https://poll.example.com",
  "deadline": "2026-09-28T00:00:00+03:00",
  "entries": [
    {
      "name": "Вариант",
      "votes": 4,
      "author": { "name": "Имя", "username": "telegram_username" },
      "imageUrl": "https://poll.example.com/image.png"
    }
  ]
}
```

`author` и `imageUrl` необязательны. Бот пишет в группу за 3 дня, 2 дня,
сутки, 12 часов, 3 часа и час до `deadline` (`CONTEST_REMIND_HOURS`)
и показывает тройку лидеров. После дедлайна он присылает вариант с наибольшим
числом голосов, с картинкой, если она есть, и упоминает автора. При равенстве
голосов объявляет ничью. Если `deadline` в JSON поменять, отсчёт начнётся
заново.

## Настройки

Все переменные записывает `bun run setup`, их можно поправить вручную
в `.env` (локально) или в переменных окружения на сервере.

| Переменная | Что это |
| --- | --- |
| `BOT_TOKEN` | токен от @BotFather |
| `CHAT_ID` | id группы |
| `THREAD_ID` | id темы в группе с темами, пусто — писать без темы |
| `OWNER_ID` | Telegram id владельца: ему приходят сообщения про сессию, на него не действуют лимиты |
| `CU_COOKIE` | сессия LMS для первого запуска на сервере, дальше бот обновляет её в `/app/data` сам |
| `REMIND_HOURS` | за сколько часов до дедлайна напоминать, по умолчанию `72,24,3` |
| `POLL_MINUTES` | как часто проверять LMS, по умолчанию `30` |
| `LIST_DAYS` | на сколько дней вперёд показывать `/deadlines`, по умолчанию `14` |
| `EXCLUDE_COURSES` | регулярное выражение: курсы с таким названием не попадают в ленту |
| `GROUP_COOLDOWN_SEC`, `PRIVATE_COOLDOWN_SEC` | лимиты на команды в группе и в личке |
| `TZ_DISPLAY` | часовой пояс в сообщениях, по умолчанию `Europe/Moscow` |
| `CONTEST_URL` | JSON с результатами конкурса, см. «Конкурс»; пусто — без конкурса |
| `CONTEST_REMIND_HOURS` | когда напоминать о конкурсе, по умолчанию `72,48,24,12,3,1` |
| `PUBLIC_URL` | адрес бота снаружи, например `https://cal.example.com`; пусто — без календаря дедлайнов |
| `PORT` | порт веб-сервера, по умолчанию `3000` |
| `SCHEDULE_ICS_URL` | iCal-ссылка на календарь с расписанием; пусто — без темы расписания |
| `SCHEDULE_THREAD_ID` | id темы для расписания |
| `SCHEDULE_TIME` | во сколько присылать пары на сегодня, по умолчанию `09:00` |
| `SCHEDULE_DAYS` | на сколько дней вперёд сообщать об изменениях, по умолчанию `7` |
| `SCHEDULE_POLL_MINUTES` | как часто проверять расписание, по умолчанию `15` |
| `SCHEDULE_ORGANIZER` | чьи события считать расписанием, по умолчанию `timetable@centraluniversity.ru` |

Если включить темы в обычной группе, Telegram поменяет её id. Тогда запусти
`bun run setup` ещё раз.

## Как это работает

LMS — это Angular-приложение поверх JSON API (`/api/micro-lms/*`). Бот читает
`/tasks/student`, а не `/deadlines`: второй скрывает задания, которые владелец
аккаунта уже сдал, а группе напоминание нужно всё равно.

Вход в `id.centraluniversity.ru` закрыт капчей и кодом из SMS, поэтому
войти можно только руками в браузере. После входа бот работает с API через
куку `bff.cookie` и сохраняет её обновлённую версию в `data/cookie.txt`.

При первом запуске бот ничего не публикует: он запоминает текущие задания
и дальше сообщает только об изменениях.

Бот видит только то, что видит аккаунт владельца: задания чужих треков
и уровней в ленту не попадут. Лишние курсы можно убрать через
`EXCLUDE_COURSES` (по умолчанию скрыто ознакомление с приказами).

# deadline-radar-cu

Telegram-бот, который следит за дедлайнами в LMS Центрального университета
(my.centraluniversity.ru) и пишет о них в группу курса или направления.

- 🆕 в LMS появилось новое задание
- 📅 / ⚠️ / 🔥 до дедлайна осталось 3 дня, сутки или 3 часа
- 🔁 дедлайн перенесли
- `/deadlines` присылает сводку на две недели и закрепляет её

Каждый запускает свою копию: бот видит LMS через аккаунт того, кто его
настроил, и присылает задания его курсов.

## Быстрый старт

Нужны [Bun](https://bun.sh) и Git.

```sh
git clone https://github.com/Igor-Abramkin/deadline-radar-cu
cd deadline-radar-cu
bun install
bun run setup
```

`bun run setup` проводит через четыре шага:

1. **Бот в Telegram.** Создаёшь бота у [@BotFather](https://t.me/BotFather)
   и вставляешь токен, мастер проверяет его.
2. **Вход в LMS.** Открывается браузер, входишь как обычно: логин, пароль,
   капча, код из SMS. Мастер сохраняет сессию в `data/cookie.txt`.
3. **Группа.** Добавляешь бота в группу и делаешь администратором с правами
   на удаление и закрепление сообщений. Потом пишешь любое сообщение в тему,
   куда бот будет присылать дедлайны. Мастер сам узнаёт id группы, темы и твой,
   проверяет права администратора и отправляет в группу проверочное сообщение.
4. **Запуск.** Мастер записывает `.env` (для запуска на своём компьютере) и
   `deploy.env` (для сервера) и показывает инструкцию для выбранного хостинга.

Инструкцию по запуску можно открыть ещё раз командой `bun run deploy`.

> `deploy.env` и `data/` дают доступ к твоему аккаунту в LMS. Они уже
> в `.gitignore`: не коммить их и никому не отправляй.

## Где запускать

Бот не принимает входящих запросов, ему нужны только исходящие соединения
с `api.telegram.org` и `my.centraluniversity.ru`. Подойдёт любая площадка,
которая умеет:

- собрать `Dockerfile` из репозитория или запустить `bun src/bot.mjs`;
- передать переменные окружения из `deploy.env`;
- хранить `/app/data` на постоянном томе. Без него после перезапуска бот
  забудет, о чём уже писал, и потеряет обновлённую сессию LMS.

Мастер показывает готовые шаги для Coolify, Dokploy и похожих панелей,
Docker Compose (`docker-compose.yml` лежит в репозитории), `docker run`,
Bun с systemd и запуска на своём компьютере.

Бот с одним токеном может работать только в одном месте. Если запустить его
на сервере, локальную копию нужно остановить.

## Команды бота

- `/deadlines` — сводка на `LIST_DAYS` дней. В группе можно писать из любой
  темы: бот удалит команду и пришлёт сводку в тему дедлайнов, закрепив её
  вместо предыдущей. В группе команда срабатывает не чаще раза в час
  (`GROUP_COOLDOWN_SEC`), повторы бот удаляет без ответа. В личке лимит —
  раз в 30 секунд на человека (`PRIVATE_COOLDOWN_SEC`).
- `/help` — что умеет бот.
- `/chatid` — id чата и твой id, только для владельца.
- `/session <cookie>` — обновить сессию LMS, только для владельца в личке.

На владельца (`OWNER_ID`) лимиты не действуют.

## Когда истекает сессия LMS

Сервер LMS продлевает сессию на 14 дней при каждом запросе, а бот ходит туда
каждые 30 минут, так что обычно она не истекает. Если всё-таки истечёт, бот
напишет владельцу в личку. Тогда:

```sh
bun run login
```

Скрипт откроет браузер, после входа выведет команду `/session …`. Отправь её
боту в личку, и он продолжит работу.

## Настройки

Все переменные записывает `bun run setup`, их можно поправить вручную
в `.env` (локально) или в переменных окружения на сервере.

| Переменная | Что это |
| --- | --- |
| `BOT_TOKEN` | токен от @BotFather |
| `CHAT_ID` | id группы |
| `THREAD_ID` | id темы в группе с темами, пусто — писать без темы |
| `OWNER_ID` | Telegram id владельца: ему приходят сообщения про сессию, на него не действуют лимиты |
| `CU_COOKIE` | сессия LMS для первого запуска на сервере, дальше бот обновляет её в `/app/data` сам |
| `REMIND_HOURS` | за сколько часов до дедлайна напоминать, по умолчанию `72,24,3` |
| `POLL_MINUTES` | как часто проверять LMS, по умолчанию `30` |
| `LIST_DAYS` | на сколько дней вперёд показывать `/deadlines`, по умолчанию `14` |
| `EXCLUDE_COURSES` | регулярное выражение: курсы с таким названием не попадают в ленту |
| `GROUP_COOLDOWN_SEC`, `PRIVATE_COOLDOWN_SEC` | лимиты на команды в группе и в личке |
| `TZ_DISPLAY` | часовой пояс в сообщениях, по умолчанию `Europe/Moscow` |

Если включить темы в обычной группе, Telegram поменяет её id. Тогда запусти
`bun run setup` ещё раз.

## Как это работает

LMS — это Angular-приложение поверх JSON API (`/api/micro-lms/*`). Бот читает
`/tasks/student`, а не `/deadlines`: второй скрывает задания, которые владелец
аккаунта уже сдал, а группе напоминание нужно всё равно.

Вход в `id.centraluniversity.ru` закрыт капчей и кодом из SMS, поэтому
войти можно только руками в браузере. После входа бот работает с API через
куку `bff.cookie` и сохраняет её обновлённую версию в `data/cookie.txt`.

При первом запуске бот ничего не публикует: он запоминает текущие задания
и дальше сообщает только об изменениях.

Бот видит только то, что видит аккаунт владельца: задания чужих треков
и уровней в ленту не попадут. Лишние курсы можно убрать через
`EXCLUDE_COURSES` (по умолчанию скрыто ознакомление с приказами).
